# Scientific decisions

This register lists the scientific and methodological choices of the project: what was chosen, why, and where the choice is owned. The linked guide explains it and the named config sets its values; change a value there, not here. A changed choice changes the identity it enters (design, Dataset, experiment or checkpoint) and needs its own comparison. Where VP1 did otherwise, the [corrigendum](Albertin_2026_PINO_Airflow_PorousMedia_corrigendum.md) point is named.

## Open choices

The defaults hold until a decision is recorded. Each change needs new identities and its own comparison.

| Question | Current default | Owner of the default |
| --- | --- | --- |

| Normalized current time (`t_n / configured_horizon`) as an input channel, in a paired ablation? | `temporal.temporal_conditioning.kind: none` | `transient_drying/base.yaml` |
| Physics weights of the steady PI experiments | Starting weights calibrated against the state MSE on the 1024 Train cases of the demo Dataset, until the PI studies have selected and the result is copied into the experiments | PI experiment configs |
| Minimum success rate of the transient plan | 0.6, to be checked against the measured rate and failure pattern of the first production campaign. The demo campaign stalled 7 of 103 ID and 10 of 26 kidney-bean attempts; every stall stood still at the check (median 32 s simulated after 900 s), while every completed case had reached 3600 s simulated after at most 686 s, so the stall rule (900 s, 3600 s) separates the two groups. At kidney bean's measured rate (0.62) the rule stops that material with about 11 % probability | Transient Dataset plan |
| Use of the physical-bound violations of the reference data | Diagnostics only. Train and Validation references of the demo Datasets: steady p up to 0.12 Pa below 0 (outlet row only) and up to 0.06 Pa above the inlet maximum (inlet row only); transient moisture never negative; T up to 4.2 K below the lowest inlet temperature in the interior of 40 of 80 cases (evaporative cooling); φ above 1 in one case (up to 1.167, hours 1–2, cold wet bed under warm inlet air, the model has no condensation). Options: per-channel tolerances, moisture on a dry basis, excluding boundary rows per channel, a physical threshold for checkpoint selection fixed on Validation only | [Prediction validity](06_evaluation.md#transient-protocols-and-metrics) |

## Steady training and physics loss

Group-weighted state MSE, three scaled physics terms, objective on normalized group RMSE; padding and embedding rationale at the end of the table.

<details>
<summary>Decision table</summary>

| Decision | Choice | Why | Owner |
| --- | --- | --- | --- |
| Data loss | MSE of the Train-scaled dimensionless states f/P (Steady nondimensionalization), pressure and velocity vector ½ each, the vector term $(E_u+E_v)/(s_u^2+s_v^2)$; `h1` adds the absolute squared gradient error with ℓ = 1 m, non-periodic derivatives in metres. | The same loss family and group weights as the selection objective and as transient drying; no weighting of cases beyond the division by their inlet pressure; the vector term keeps the Euclidean velocity geometry. VP1: periodic stencil and batch sum (corrigendum 5, 8) | [Data loss and selection objective](05_training.md#data-loss-and-selection-objective), `configs/03_learning/steady_flow/base.yaml` (`loss.data`) |
| Physics terms | Three dimensionless terms, each with its own weight and linear warm-up: momentum, cross-section flux balance, boundary (inlet mismatch plus squared outlet mean per case); scales from the inputs only | Each term weighted on its own, in comparable units. VP1: one unscaled sum and a batch-pooled outlet (corrigendum 8, 9) | [Steady flow](05_training.md#steady-flow), PI experiment configs (`loss.physics`) |
| Viscous stress | COMSOL's Brinkman stress (μ/ε)(∇u + ∇uᵀ − ⅔(∇·u)I), trace term kept | Same stress as the solver that produced the reference (corrigendum 13) | [Steady flow](05_training.md#steady-flow) |
| Continuity | Flux balance through each row instead of pointwise ∇·u or ∇·(εu) | The interpolated COMSOL solution is not pointwise divergence-free on the grid, while its flux balance nearly vanishes (corrigendum 14) | [Steady flow](05_training.md#steady-flow) |
| Starting weights | Momentum 10⁻¹, continuity 10, boundary 10, warm-up over 100 passes over the full Train set (counted like the budget, so a Train subset ramps over the same budget fraction); the PI studies search the three weights two decades around these values | Each term equals the state-MSE data loss at a smooth 1 % field error (calibrated on the 1024 Train cases of the demo Dataset, the same powers of ten as on the two smoke cases; repeated on the production Train set before the PI studies) | [Steady flow](05_training.md#steady-flow), [Optuna and tracking](05_training.md#optuna-and-tracking) |
| Derivatives and crop | The maintained physics configs use `physical` (finite-difference) derivatives with `interior_crop: 2` on the momentum term; `spectral` always uses Fourier continuation | The Brinkman wall layer is far below the grid spacing, so the uncropped wall columns would dominate the momentum term of the exact solution; the bed is not periodic (corrigendum 2, 6) | [Steady flow](05_training.md#steady-flow), PI experiment configs (`loss.physics.derivatives`), the code default `interior_crop: 2` (`experiments_config_defaults.py`) |
| Objective | `normalized_group_macro_rmse` over the pressure and velocity groups; case errors averaged equally over the cases of a material and over the materials before each root; drives checkpoint selection, the plateau comparison schedule, studies and the notebook ranking. | Dimensionless, with equal weight for the pressure and the velocity group. VP1: batch-summed RMSE in mixed units (corrigendum 3) | [Steady flow](05_training.md#steady-flow), `steady_flow/base.yaml` (`evaluation.objective`) |
| Optimization | AdamW with weight decay 10⁻⁴; half-cosine learning rate over a budget of 600 passes over the full Train set (starting value until the budget derivation, [Training](05_training.md#budget-schedule-and-validation-points)), counted in seen units, with validation, OOD and physics monitor at its 20 points (see the schedule rows under transient training); k = 16 cases per update; float32 without mixed precision | Defaults outside the study search spaces; half-precision cuFFT needs power-of-two grids (251 × 401 is not) and finite-difference physics derivatives lose their accuracy in half precision | `steady_flow/base.yaml` (`optimizer`, `scheduler`, `training`, `data`) |
| Architectures | FNO and U-NO with physics-informed twins of identical architecture and learning rate; mode counts ordered [Y, X], the U-NO mode ratio stated in full; U-NO lifting and projection widths 2 × hidden channels like the FNO | Twins isolate the effect of the physics loss (corrigendum 22 for the axis order); neuraloperator's fixed 256 would not scale with the width | [Configurations](05_training.md#configurations), `steady_flow/experiments/architecture_comparison/` |
| Coordinates and padding | The seven input channels carry `x` and `y` explicitly, so `positional_embedding: null`; `domain_padding: 0.1` (10 % zero padding per side of the lifted field) | The grid embedding is periodic without endpoint and would give one physical point different coordinates at different strides; the fields are not periodic, so padding keeps the FFT wrap-around away from the boundaries | [Configurations](05_training.md#configurations), `steady_flow/base.yaml` (`model.params`) |

## Transient training

Matched A0 → {B, A1} protocol, rollout curriculum, one selection rule, bounded `tanh` RNO cell.

<details>
<summary>Decision table</summary>

| Decision | Choice | Why | Owner |
| --- | --- | --- | --- |
| Protocol | Matched A0 → {B, A1}: teacher-forced A0, then autonomous B and teacher-forced A1, both from A0's selected checkpoint, of which they keep only the model, Adam's moments and step counter (never its scheduler state; each stage starts a fresh budget and schedule) and continue only the random stream of A0's sampler at a fresh epoch; B trains K × N supervised transitions with A0's K (one K for every architecture) and A1 B's actual transitions, which it may exceed by at most one optimizer group; B and A1 run on one GPU model; each stage also reports its optimizer steps, gradient predictions and optimisation seconds | Compares training protocols at equal supervised data; a time budget would make the step count depend on hardware and node load | [Matched comparison](05_training.md#matched-comparison-a0--b-a1), `configs/03_learning/transient_drying/base.yaml` (`training`) |
| Rollout curriculum | B rolls out 2 → 4 → 8 → 16 → 32 steps at budget fractions 0, 0.2, 0.4, 0.6, 0.8 in windows of 32 transitions; windows start every 32 transitions, plus one that ends at the trajectory end (its overlap counts twice), a case shorter than the window forms one window with every horizon capped at its length, and each window draws its own horizon and origin, the origins rotating over the three thirds of the window | Grows the autonomous horizon gradually; every Train case trains, whatever its length | [Matched comparison](05_training.md#matched-comparison-a0--b-a1), `base.yaml` |
| Checkpoint selection | Every stage and architecture selects by `normalized_drying_group_macro_rmse` (T and φ 1/3, w_surf and w_int 1/6) on autonomous rollouts of whole validation trajectories; each case is averaged over its grid and steps, cases equally within a material and materials equally before each root, as in the plateau comparison, Optuna and the notebook ranking; every stage validates at the 20 points of its own budget | One rule for every stage and architecture, measured on autonomous prediction; long trajectories and materials with many cases do not dominate | [Data loss and selection objective](05_training.md#data-loss-and-selection-objective) |

| Inputs | 28 ordered channels with explicit coordinates and no normalized-time channel (see open choices above); training on the full 251 × 401 grid (`data.spatial_stride: 1`, as in steady flow); stride 2 (126 × 201) only for the stride comparison. | One grid mechanism for both tasks; the endpoint-preserving stride keeps both boundaries in a coarser grid; artifacts use the full grid | [Inputs, scaling and grid](05_training.md#inputs-scaling-and-grid), `base.yaml` (`data`) |

## Evaluation

Per-field metrics in physical units, one physics yardstick, transient protocols, validity rules and like-with-like comparisons.

<details>
<summary>Decision table</summary>

| Decision | Choice | Why | Owner |
| --- | --- | --- | --- |
| Field metrics | One implementation for both tasks, used by validation, artifacts and notebooks. Primary: physical and scaled RMSE and MAE per field, each case's mean, then equal over the cases of a material and over the materials, RMSE rooted after the mean. Secondary: relative L2 (full grid) and H1 (interior without two cells per edge, √∫(f² + (1 m)²·\|∇f\|²), derivatives in metres, no time derivative) on physical fields, √(E/R) per case and field before the same mean; transient per time point and over the horizon from each case's summed energies. A summary averages fields within their group, then the groups equally. | Per-case ratios as in the FNO and neuralop losses and PDEBench; summing energies over cases would weight by reference energy and hide poor small-norm cases (norms 100 and 1 with errors 10 % and 100 %: summed 10 %, per case 55 %). RMSE and the relative norms may rank runs differently; relative T errors in kelvin stay secondary. VP1: one undefined norm over concatenated fields (corrigendum 3) | [Field metrics of both tasks](06_evaluation.md#field-metrics-of-both-tasks) |
| Near-zero reference | A relative norm whose case reference RMS is below the field's floor (p 1 Pa, u and v 10⁻⁴ m/s, T 1 K, φ 10⁻³, w_surf and w_int 0.1 kg/m³) is unavailable and counted, never zero and never epsilon-stabilized; a transient state below its floor stays in the horizon energies | A stabilized ratio would report an arbitrary value for a field with nothing to compare | [Near-zero references and ranking](06_evaluation.md#field-metrics-of-both-tasks) |
| Physics yardstick | Every steady run's physics terms are re-evaluated with physical finite differences, momentum on the `EVAL_PAD` interior, whatever derivative it was trained with; reference fields pass the same functions | One yardstick for all runs. VP1: different crops and drag for models and reference (corrigendum 6, 7) | [Steady case metrics](06_evaluation.md#steady-case-metrics), [Component checks](06_evaluation.md#component-checks) |
| Transient protocols | Teacher-forced one-step, full autonomous rollout and rolling origins; horizons 1, 2, 4, 8, 16, 32, 64 and 128 transitions plus full, each with cumulative and endpoint reductions; a horizon longer than a case is recorded as unsupported; the RNO's one-step records and rolling origins start from the state of a teacher-forced pass over the reference prefix, its full rollout from its own state | Separates one-step accuracy from error growth | [Transient protocols and metrics](06_evaluation.md#transient-protocols-and-metrics) |
| Validity | Predictions are never clamped, filtered or imputed; a transient state is physically invalid when T leaves [0, 2000] K, φ leaves [0, 1.10] or a moisture field is negative, with the 2 × 2 corner blocks of every channel excluded from that count but not from the non-finite count; physical-bound violations are diagnostics only and are fed back; an autonomous rollout stops only the affected case at its first non-finite value; steady cases are valid or non-finite | The φ tolerance admits the slight supersaturation of the reference itself, an accepted model limit to re-check on production data (the demo reference exceeds it in one case, 1.167, see Open choices); stopping at a finite bound violation would end trajectories the error metric still scores and hide the violation's later course | [Prediction validity](06_evaluation.md#transient-protocols-and-metrics) |

| Evaluation grid | Artifacts on the full 251 × 401 grid, independent of the training stride | Metrics on the generated resolution | [Evaluation grid](06_evaluation.md#evaluation-grid) |

## Justified task differences

Both tasks share one training, selection and evaluation implementation and differ only where the physics or the temporal structure requires it. Each difference below is kept on purpose; every other setting is common. The last row holds execution settings, which change no scientific result.

<details>
<summary>Decision table</summary>

| Difference | Steady flow | Transient drying | Paper sentence | Owner |
| --- | --- | --- | --- | --- |
| Inputs and target | Seven inputs (coordinates, log-permeabilities, cross ratio, porosity, inlet pressure) to the absolute field $(p, u, v)$ | 28 inputs (current state, airflow, material fields and coefficients, interval forcing) to Train-scaled increments added to the current state | "The flow operator maps permeability, porosity and pressure forcing to a stationary pressure–velocity field, whereas the drying operator advances a coupled thermal–moisture state by zero-preserving, state-scaled increments from fixed airflow, material coefficients and interval boundary forcing." | Task specifications in `src/domain/tasks/` |
| Groups | Pressure and the velocity vector, ½ each | T and φ ⅓ each, w_surf and w_int ⅙ each | "Velocity components form one physical vector and are scored jointly, whereas surface and internal moisture are distinct scalar compartments and retain separate normalized errors; physical groups receive equal weight in the selection objective." | [Data loss and selection objective](05_training.md#data-loss-and-selection-objective) |
| Rollouts and horizons | One prediction per case | Teacher-forced one-step, autonomous rollouts and rolling origins over horizons up to each case's available trajectory | "Drying evaluation separates one-step accuracy from error growth along autonomous rollouts over the available trajectory of each case, whereas stationary flow requires only one prediction per case." | [Transient protocols and metrics](06_evaluation.md#transient-protocols-and-metrics) |
| Recurrence and autonomous checkpoint choice | Stateless models, selected on single fields | RNO hidden state with truncated backpropagation; every architecture selected on complete autonomous validation trajectories | "Autonomous drying predictions feed errors back into subsequent inputs, so training distinguishes teacher forcing from self-feeding, recurrent models carry hidden state through truncated backpropagation, and checkpoints are selected on complete autonomous validation trajectories." | [Matched comparison](05_training.md#matched-comparison-a0--b-a1) |
| B against A1 at equal supervised transitions | Single run | B and A1 continue the same A0; B trains K × N supervised transitions and A1 exactly those B committed, on one GPU model, with their optimisation seconds reported | "To isolate rollout exposure from additional optimization, B and A1 start from the same selected A0 model and optimizer state and are trained on the same number of supervised transitions on the same GPU model; their optimization time is reported alongside." | [Matched comparison](05_training.md#matched-comparison-a0--b-a1) |
| Sequence artifacts | One predicted field per case | Per case the predicted state sequence of every prediction chain over physical time | "Drying artifacts keep each case's predicted state sequences over physical time, because accumulated error and its growth are what the protocols compare; a stationary artifact holds one field realization per case." | [Transient protocols and metrics](06_evaluation.md#transient-protocols-and-metrics) |
| Physics loss | The physics-informed twins add three scaled residual terms (momentum, flux balance, boundary) to the data loss | Data loss only; the transient physics loss is disabled in the current program | "Physics-informed flow models add scaled residuals of the steady Brinkman equations to the data loss, whereas the drying models are trained on data alone." | [Steady flow](05_training.md#steady-flow), [Data loss and selection objective](05_training.md#data-loss-and-selection-objective) |
| Execution settings | Memory batch 16 cases, evaluation batch 32 cases, 8 loader workers | Memory batch 2 units, evaluation batch 2 whole trajectories, loading in the main process | None: they set memory use and loader speed (transient evaluation holds whole trajectories; the loader benchmark measured the fastest worker count per task) and change only floating-point rounding or speed, never the science | `base.yaml` of each task (`training.memory_batch`, `data`) |
